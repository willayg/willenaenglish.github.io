# V1 Level Test Refactor Plan

**Date:** 2026-09-12

The goal is **not** to abandon what we learned from V2. V2 stays intact as a reference implementation and design source. We use it to modernize V1 so that we end up with **one shared level-test engine**, not two competing systems.

## 1. Freeze and map current V1 behavior
Before changing architecture, document the current V1 flow and dependencies:

- setup flow
- question loading
- adaptive selection
- reading rendering
- listening rendering/playback
- sentence unscramble
- answer handling
- scoring
- result calculation
- recording
- student wrapper behavior
- visitor/free test behavior

This gives us a known-good baseline so we can refactor without accidentally changing test behavior.

## 2. Split `app-classic.js`
`app-classic.js` currently does too much. Break it into focused modules while preserving behavior.

Target structure:

- `assessment-state.js`
- `assessment-selector.js`
- `assessment-renderer.js`
- `assessment-listening.js`
- `assessment-scramble.js`
- `assessment-navigation.js`
- `assessment-results.js`
- thin `app-classic.js` as the orchestrator

First pass should be a structural refactor only. No content or difficulty changes.

## 3. Create one canonical question model
Bring the good ideas from V2 `question-model.js` into the shared engine.

Every question coming from Supabase should be normalized into one predictable shape before rendering.

The model should support:

- question id
- level
- type
- prompt
- passage
- choices
- canonical answer
- metadata
- listening data
- scramble tokens
- visual answer metadata

The renderer should never need to care how the raw DB row was structured.

## 4. Create one canonical assessment renderer
This becomes the renderer used by all computerized level tests.

It should support:

- normal text multiple choice
- reading multiple choice
- listening multiple choice
- sentence unscramble
- number/time answer choices
- image/SVG answer choices
- mixed text/image choices where needed
- future typed-answer support without another rewrite

The objective is:

**one renderer for student test, visitor test, free test, and any future V2-style flow.**

## 5. Add backward-compatible image choices
Do not replace text answers in the DB.

Each answer should retain a canonical text value, with optional visual metadata.

Conceptually:

```json
{
  "label": "toothbrush",
  "choice_type": "image",
  "asset_key": "toothbrush"
}
```

The grading system grades `"toothbrush"`.

The renderer decides whether to show text, an image, or both.

Old text-only questions continue working unchanged.

## 6. Add a shared Noto visual asset system
Use the Noto SVG set for visual questions and speaking prompts.

Create one shared asset folder and resolver, for example:

```text
toothbrush -> /Assets/level-test/noto/toothbrush.svg
apple      -> /Assets/level-test/noto/apple.svg
bus        -> /Assets/level-test/noto/bus.svg
```

Use the same assets everywhere:

- computerized test answers
- speaking prompts
- visitor test
- future visual activities

Include the Apache 2.0 notice properly in the project.

## 7. Bring V2 session/state improvements into V1
Use V2 as the reference for cleaning up the session architecture.

Improve:

- centralized session state
- cleaner answer recording
- reliable current-question state
- persistent state where useful
- back/exit handling
- session-loss warnings
- fewer global variables
- less duplicated state between wrappers

## 8. Bring V2 navigation ideas into V1
Unify the test controls so question types do not each invent their own interface.

Create consistent shared controls for:

- previous/back where appropriate
- answer selection
- next
- progress
- listening playback state
- exit warning

The computerized test should feel like one application regardless of question type.

## 9. Bring the V2 speaking assessment over as a separate module
Do not stuff speaking logic into `app-classic.js`.

Keep it as its own assessment phase/module using the V2 work:

- 3-question speaking assessment
- level-by-level speaking prompts
- scoring
- teacher-selected speaking level
- app recommendation
- computer-test starting-level recommendation
- teacher override
- notes
- confidence calculation

Reuse the V2 files/logic where sensible rather than rewriting from memory.

## 10. Replace speaking visuals with Noto assets
Update the speaking prompts so their visual elements use the same Noto asset system.

This gives us consistent visuals across:

- speaking assessment
- image-answer questions
- visitor test
- computerized test

## 11. Add speaking to the visitor / face-to-face flow
The visitor flow should become roughly:

**Student details → Speaking assessment → Teacher review/recommendation → Computerized test → Result**

The teacher can:

- accept the recommended computer starting level
- manually override it
- record notes

The computerized test should consume the chosen start level.

## 12. Audit Level 3 reading
Review every eligible Level 3 reading question.

Check for:

- language above the level ceiling
- weak distractors
- questions where the answer is copied directly from the passage
- awkward or unnatural English
- questions that are really vocabulary matching rather than reading comprehension
- excessive sentence length
- untaught grammar
- ambiguous answers

Level 3 should test comprehension using very controlled language.

Use more variety:

- image answers
- number/time answers
- simple location understanding
- present simple vs present continuous
- basic daily activities
- true/false where suitable
- simple sequencing only where the language itself is safe

## 13. Audit Level 4 reading
Review Level 4 as the bridge between basic and genuinely diagnostic reading.

Increase thinking demand without increasing language beyond the level.

Focus on:

- connecting two simple facts
- locating information among distractors
- basic contrast
- simple sequence
- matching actions to people
- everyday routines
- location relationships
- slightly less direct questions

Avoid making Level 4 “harder” by simply using longer passages.

## 14. Audit Level 5 reading
Level 5 should begin to separate stronger learners from students who can only perform direct word matching.

Review for:

- excessive literalness
- poor distractors
- language that accidentally jumps too far
- whether the item actually measures reading rather than vocabulary recognition

Allow more:

- inference from simple information
- combining two details
- sequence
- cause/result within taught language
- identifying what is happening now versus habit/routine

## 15. Audit Level 3 listening
Review every Level 3 listening item.

Look for:

- overly obvious answers
- answer wording copied directly from the audio
- weak distractors
- prompts that test vocabulary recognition only
- unnecessary grammar difficulty

Keep the audio language simple while making the listening decision meaningful.

## 16. Audit Level 4 listening
Create a clearer step up from Level 3.

Use:

- similar-sounding distractors
- information order
- locations
- times
- simple actions
- selecting between two plausible answers

Still stay strictly inside the language ceiling.

## 17. Audit Level 5 listening
Level 5 should start becoming properly diagnostic.

Use:

- slightly denser information
- two-detail comprehension
- simple inference
- distinguishing habit from current action
- stronger distractors
- short dialogues where useful

Do not manufacture difficulty with fast speech or advanced grammar.

## 18. Calibrate Reading 3 → 4 → 5
After auditing individually, compare the three levels side by side.

We need a real progression:

- **Level 3:** understand one clear piece of information
- **Level 4:** connect or discriminate between simple pieces of information
- **Level 5:** combine details and make limited inference

The linguistic ceiling must still rise gradually.

## 19. Calibrate Listening 3 → 4 → 5
Do the same progression check for listening.

The difference between levels should come primarily from **comprehension demand**, not vocabulary or grammar jumps.

## 20. Update the DB only after renderer support is ready
Once image choices and the canonical renderer are deployed safely:

- replace weak Level 3 reading
- replace weak Level 4 reading
- replace weak Level 5 reading
- replace weak listening 3/4/5 items
- add image-based choices
- add numeric/time choices
- retain text labels for backward compatibility

Do not push image-only data before every active test path can render it.

## 21. Recalibrate adaptive selection
Only after the content itself is trustworthy should we tune the adaptive engine.

Review:

- starting ability
- speaking-derived starting level
- level movement after correct/wrong answers
- repeated wrong-answer penalty
- subject/type balancing
- reading/listening frequency
- grammar limits at lower levels
- question difficulty metadata

Otherwise we would be calibrating around bad questions.

## 22. Make all test entry points use the same core
End state:

**Shared:**
- loader
- question model
- renderer
- grader
- adaptive selector
- listening system
- asset resolver

**Different wrappers/configurations:**
- student level test
- visitor / face-to-face test
- free/public test
- internal/admin testing

They should differ in flow and permissions, not question rendering.

## 23. Keep V2 intact until parity is reached
Do not delete V2.

Use it as the reference for:

- speaking design
- session structure
- recommendations
- navigation
- question model
- future features

As each V2 idea is absorbed into the shared V1 engine, note where it moved.

Only archive V2 after V1 clearly contains everything we want.

# Recommended build order

## Phase A — architecture
Split `app-classic.js` and isolate the renderer.

## Phase B — canonical model/rendering
Normalize question data and make one renderer handle all current question types.

## Phase C — visual answers
Add Noto assets and image/number/time choice support.

## Phase D — regression
Make sure existing student/free/visitor tests still behave correctly.

## Phase E — speaking
Bring the V2 speaking assessment and recommendation system into the visitor flow.

## Phase F — content audit
Audit and rebuild Reading Levels 3, 4, 5 and Listening Levels 3, 4, 5.

## Phase G — DB migration
Publish the improved questions and visual metadata.

## Phase H — adaptive calibration
Tune the computerized test using the improved content and speaking-derived start level.

## Phase I — consolidation
Make all level-test entry points use the same engine and retire duplicated code.
